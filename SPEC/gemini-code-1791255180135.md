# 📄 SPEC - Armário Virtual (Virtual Closet)

## 1. Visão Geral e Arquitetura
Sistema web para gestão de guarda-roupa pessoal, montagem de combinações em quadro visual interativo (*board*), criação de coleções temáticas e planejamento de compras com simulador de estilo (*wishlist*).

### Tech Stack & Bibliotecas CDN
- **Frontend:** HTML5, CSS3, JavaScript Vanilla (ES6+).
- **Dependências de Script (CDN):**
  - `@supabase/supabase-js` (Cliente de integração com banco de dados, auth e storage).
  - `lucide` / `lucide-icons` (Biblioteca de ícones SVG limpos).
- **Backend & Database:** Supabase (Auth, PostgreSQL DB, Storage Buckets).
- **Processamento de Imagem:** Microsserviço/API Open Source de remoção de fundo (`rembg`).
- **Hospedagem:** GitHub Pages (Repositório no GitHub).

---

## 2. Diretrizes de Interface (UI / UX)
- **Visual:** Estilo limpo, fundo branco predominante (`#FFFFFF`), tipografia moderna e alto contraste.
- **Dispositivos Alvo:** Exclusivo para telas de **Tablet** e **Desktop** (ponto de interrupção mínimo: 768px).
- **Simbologia:** Proibido o uso de emojis na interface do usuário. Utilizar exclusivamente a biblioteca **Lucide Icons**.
- **Recursos Nativos:** Acesso à câmera (`navigator.mediaDevices.getUserMedia`) e File Upload API somente em fluxos de cadastro de peças.

---

## 3. Requisitos Funcionais (RF)

### RF01 - Autenticação & Onboarding
- **RF01.1:** Login e cadastro via Supabase Auth.
- **RF01.2:** Tela inicial com saudação personalizada ("Bem-vindo, [Nome]") e ambiente limpo.
- **RF01.3:** Ações rápidas: **[Adicionar Peça]** e **[Criar Coleção]**.

### RF02 - Gestão de Peças e Estoque
- **RF02.1:** Upload de imagens via arquivo (Desktop) ou Câmera (Tablet/Mobile).
- **RF02.2:** Modal de tutorial de fotografia no primeiro uso (com opções "Pular" e "Não mostrar novamente").
- **RF02.3:** Processamento assíncrono para remoção de fundo via IA Open Source.
- **RF02.4:** Atributos da peça: Categoria/Tipo, Cor, Estação (Primavera, Verão, Outono, Inverno, Atemporal) e Formalidade.
- **RF02.5:** Gestão de status: `Ativo`, `Vou me desfazer`, `Arquivado`.

### RF03 - Board Visual (Lookbook Interativo)
- **RF03.1:** Área interativa *drag-and-drop* para arrastar, redimensionar, girar e sobrepor peças em PNG.
- **RF03.2:** Salvamento do estado do board (matriz de coordenadas $x, y$, escala e ordem de camada $z-index$).
- **RF03.3:** Geração automática de imagem estática de exibição (capa) ao salvar o look.

### RF04 - Coleções Temáticas
- **RF04.1:** Criação e listagem de coleções (ex: "Halloween 2026", "Trabalho").
- **RF04.2:** Associação de combinações/outfits dentro de coleções.

### RF05 - Wishlist e Comparador
- **RF05.1:** Cadastro de peças desejadas com upload de imagem e registro de preço.
- **RF05.2:** Teste de combinação no Board misturando itens da Wishlist com itens do guarda-roupa atual.
- **RF05.3:** Ações da Wishlist: **Marcar como Comprada** (converte para o guarda-roupa) ou **Arquivar/Fechar** (mantém no histórico para consulta futura).

## 4. Instruções Essenciais para Agentes de IA (ex: Google Jules)
1. **Regra de Ausência de Dúvidas:** Se houver qualquer ambiguidade ou detalhe não especificado nesta SPEC, **NÃO codifique**. Pare a execução e solicite esclarecimento.
2. **Decomposição em Tarefas:** Sempre divida programações ou implementações extensas em tarefas pequenas e subtarefas incrementais.
3. **Registro de Progresso (`backlog.md`):** Mantenha e atualize continuamente um arquivo `backlog.md` na raiz do repositório. Registre todas as funcionalidades implementadas, ajustadas ou alteradas com os status:
   - `[ ]` Pendente
   - `[/]` Em Andamento
   - `[x]` Concluído
4. **Proibição de Gerenciadores de Pacotes:** Não utilize `npm`, `vite`, `webpack` ou crie arquivos `package.json`. Todas as bibliotecas externas devem ser importadas diretamente no HTML via CDN oficial.
